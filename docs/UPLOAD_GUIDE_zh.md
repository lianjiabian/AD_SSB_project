# 手工上传GitHub

## 上传范围

只上传 `UPLOAD_TO_GITHUB` 文件夹**里面的全部内容**，包括 `.github`、`.gitignore`、`.gitattributes`。不要把上一级目录、同级私有目录或整个本地分析项目上传。提供的 `SSB_GITHUB_PUBLIC_FINAL_20261022.zip` 也只包含这个公开目录。

本地 `PRIVATE_DO_NOT_UPLOAD` 包含本机路径、受限审核断言和敏感性病例配置，仅用于有权限的本地复现，绝不能随仓库发布。`.gitignore`不能替代上传前检查，尤其网页上传可绕过本地Git忽略规则。

## 操作建议

1. 先核对仓库权限、代码归属和是否允许公开；本阶段未指定开源许可证，不要在GitHub创建页面自动勾选MIT等许可证。
2. 创建自己的空仓库。仓库名称和URL由作者决定，本次没有创建或关联任何远程仓库。
3. 将公开目录内容上传到仓库根目录。命令行方式能保留隐藏文件；如使用网页方式，要特别检查 `.github/workflows/ci.yml` 是否存在。
4. 查看Actions结果。自动检查只验证公开代码语法、合成公式和文件安全，**不会**上传或运行真实患者数据。
5. 可将当前内容标记为 `v1.0.0`，并在正式出版时补充确认后的作者信息、软件引用和实际仓库/归档标识。不要填写尚不存在的DOI。

```bash
# 在公开目录内操作；以下命令由作者自行执行，未在本次任务中运行。
git init
git add .
git diff --cached --stat
git status --short
# 核对暂存内容后再commit；remote由作者自己填写，不在此虚构。
```

## 可选完善，不阻止保存本地代码文件

- 确认作者、维护者和正式仓库URL后填写软件引用；当前不伪造CITATION.cff作者。
- 若后续决定开源，获得代码权利人授权后添加合适的软件许可证；不要把软件许可延伸到临床或第三方数据。
- 投稿前另行完成伦理/同意及数据访问流程。代码可见不代表临床数据可以公开，也不表示无数据即可复现临床效果。

当前版本仍保留固定队列的必要人数和方法定义，但不公开真实逐例名单或硬编码患者审核值。

## 日后修改代码

检查并确认修改内容后，在仓库根目录运行 `python3 tools/build_manifest.py` 更新校验清单，再运行 `python3 tools/check_release.py --verify-hashes`。不要通过单纯重建校验清单来掩盖未经审核的数据加入；清单完整性检查不代替隐私审查。
